## Technik
- Statische Single-Page-App, Vanilla ES-Module, **kein Build-Schritt**, Hash-Router in `assets/js/app.js` (Routen-Tabelle oben).
- Daten: Jolpica (live), OpenF1, Open-Meteo, Wikimedia; täglicher Snapshot und Archiv in `data/` (erzeugt von `scripts/update.mjs` via GitHub Action 06:00 Zürich).
- News: RSS (Formel1.de, Formula1.com) → `scripts/news.mjs` alle 2 h → `data/news.json`. Logik in `assets/js/news-feed.js` (rein, getestet).
- **Aktualität ohne KI (16.10.2026):** `data/editorial.json` (Upgrades, Verträge, Strafen, Regeln …) wird nur von der KI-Recherche in `update.mjs` neu geschrieben – die ist aus, also altert sie. Zwei Gegenmittel, beide gratis:
  - **Fahrerfeld der nächsten Saison aus Wikipedia** (Schritt 5b in `update.mjs`, läuft täglich und immer): Wikitext des Artikels «<Jahr+1> Formula One World Championship» über die Action-API, Abschnitt `== Entries ==` parsen. Reine Logik in `assets/js/wiki-grid.js` (`parseEntryTable`, `teamIdOf`, `driverIdOf`, `mergeContracts`), getestet in `tests/wiki-grid.test.js` gegen `tests/fixtures/wiki-2027.txt`. `mergeContracts` **stuft nur hoch** und lässt recherchierte Notizen/Quellen stehen; einzige Herabstufung: hat Wikipedia bei einem Team beide Cockpits besetzt, wird ein widersprechendes Gerücht auf «offen» gesetzt. Fehlen in der Tabelle ist kein Beweis – dort stehen nur unterschriebene Verträge. Sicherung: unter 16 gelesenen Cockpits wird gar nichts geschrieben. Ergebnis in `editorial.contracts` + `contractsUpdatedAt`.
  - **Frische RSS-Meldungen auf den Fachseiten**: `newsSection()` in `shared.js` (nutzt `relatedNews()` aus `news-feed.js`, filtert nach den Tags aus `news.json`) steht unter Upgrades, Transfers, Regeln und Strafen. `staleNote()` sagt offen, wenn die recherchierten Daten älter als 10 Tage sind.
- Tippspiel-Backend: **Supabase** (Postgres + Auth E-Mail/Passwort, Gratis-Plan). Schema und alle Regeln in `supabase/01_tippspiel.sql`:
  - RLS + Trigger erzwingen Tippschluss, Sichtbarkeit (fremde Tipps erst nach Tippschluss), Admin-Rechte, Fahrer-Validierung.
  - Browser ruft fast nur RPC-Funktionen auf (`season_data`, `my_groups`, `create_group`, `join_group`, `event_state`, `save_tips`, `group_event`, `delete_account` …), alle liefern JSON.
  - **Achtung beim erneuten Einspielen:** alle Tabellen sind `create table if not exists`, Funktionen dagegen `create or replace`. Geänderte **Spalten oder `check`-Constraints werden also nicht nachgezogen** – eine bestehende Tabelle bleibt auf dem alten Stand. Für solche Änderungen braucht es unter der Tabelle ein eigenes `alter table … drop constraint if exists` + `add constraint` (so gelöst bei `tip_reactions.emoji`, siehe 16.10.2026 unten).
  - `events`/`season_drivers` schreibt nur der Sync-Job `scripts/tippspiel.mjs` (GitHub Action alle 10 Min., Kalender/Fahrerfeld aber nur zur vollen Stunde; Resultate werden nur alle 10 Min. geprüft, wenn eine Session – Quali/Sprint/Rennen – höchstens 3 h zurückliegt, sonst stündlich («Hot Window»). Service-Key als GitHub-Secret.
- **Demo-Modus** (ohne Supabase-Zugangsdaten in `config.js` oder mit `?demo`): dasselbe SQL in **PGlite** (Postgres als WASM) im Browser, plus `supabase/dev/compat.sql` (auth-Schema, Rollen). Code: `assets/js/tipp/dev.js`, `pg.js`.
- Tests: `tests/*.test.js` mit Mini-Harness, laufen im Browser (`/tests/`) und in Node (`npm test`, GitHub Action `tests.yml`). DB-Tests gegen echtes Postgres (PGlite).
- Lokaler Server auf dem Mac: `python3 -m http.server 8899`, Vorschau-Konfiguration in `.claude/launch.json` («pitwall-mac»); auf dem alten Windows-PC: `tools/serve.ps1` («pitwall»).
- Node ist jetzt lokal verfügbar (`nvm`, Node 22) → `npm install && npm test` läuft direkt auf dem Mac.
- **Online seit 15.10.2026:** Repo `przw48wp29-bit/pitwall` (öffentlich), Live-Seite `https://przw48wp29-bit.github.io/pitwall/` (Pages aus `main` / root). Der Arbeitsordner ist das Git-Repo; Elias pusht über **GitHub Desktop** (kein `gh`, kein Token auf dem Mac). Secrets `SUPABASE_URL`/`SUPABASE_SERVICE_KEY` sind gesetzt, alle Actions laufen grün.
  - **`data/` gehört den Actions**: `season.json`, `races/`, `news.json`, `meta.json`, `calendar.ics`, `champions.json`, `careers.json` erzeugt der Server. Lokale Stände nie darüberschreiben – sonst wirft man die frischen Daten weg.
  - `core.fileMode false` ist gesetzt (die Dateien kamen ursprünglich von Windows, sonst meldet Git lauter Schein-Änderungen).

  - **Fehler «violates check constraint tip_reactions_emoji_check» (16.10.2026):** Die Live-Datenbank hatte eine ältere, kürzere Emoji-Liste. Weil die Tabelle mit `create table if not exists` angelegt wird, zog das erneute Einspielen den Constraint nie nach. Gelöst mit einem `alter table`-Block direkt unter der Tabelle (läuft bei jedem Einspielen, auch mehrfach, und behält bestehende Reaktionen). Abgesichert durch den Test «Jedes angebotene Emoji wird von der Datenbank akzeptiert» in `tests/db.test.js`, der die Liste im JS gegen die im SQL prüft **und** jedes Emoji einmal wirklich speichert. Klick auf einen Pick zeigt im Popover **wer** reagiert hat (bei eigenen Tipps nur diese Liste, ohne Emoji-Auswahl), zusätzlich als `title`-Tooltip. Realtime über `live()` in `api.js` (Supabase-Channel; im Demo-Modus wirkungslos, weil die DB nur lokal läuft) – dafür muss die Tabelle in der Publikation `supabase_realtime` sein (macht das SQL selbst) **und Realtime im Supabase-Dashboard für die Tabelle aktiviert sein**. Aufräumen beim Seitenwechsel über `onLeave()` in `shared.js`.
- **Weltmeistertitel (15.10.2026, Live-SQL muss Elias neu einspielen):** Wer eine Saison in der Gruppe gewinnt, bekommt einen dauerhaften Titel. Tabelle `group_titles` (unveränderlich, nur `select` für Mitglieder; `name` ist bewusst eine Momentaufnahme und es gibt keinen FK auf `memberships`, damit der Titel auch nach Austritt oder Kontolöschung stehen bleibt). SQL: `season_ranking` (Feinwertung Punkte → exakte Treffer → Wochenendsiege), `season_open_events`, `group_titles_of`, `close_season`; beide erstgenannten sind für `authenticated` gesperrt. `group_detail`, `group_standings` und `group_event` liefern `titles`, `group_standings` zusätzlich `can_close`.
  - **Abschluss macht der Admin von Hand** («Saison abschliessen» in der Rangliste, mit Rückfrage – endgültig), damit späte Korrekturen noch möglich sind. Offen heisst: ein Wochenende steht noch an **oder** jemand in der Gruppe hat getippt und das Resultat fehlt. Rennen, die vor der Gruppe stattfanden (niemand hat getippt), zählen bewusst nicht – sonst liesse sich die Testsaison ab Rennen 18 nie abschliessen.
  - Bei Punktgleichheit entscheidet die Feinwertung; nur bei komplettem Gleichstand teilen sich mehrere den Titel (`lead = 0`). Keine weiteren Auszeichnungen (Vize, Rekorde) – bewusst schlank.
  - UI in `assets/js/tipp/titles.js`: ★-Sterne beim Namen (überall, Tooltip mit Saisons), «Hall of Fame»-Karte auf der Gruppenseite, Champion-Banner in der Rangliste, Admin-Karte «Saison abschliessen». Stile unter «Weltmeistertitel» in `tipp.css`.
